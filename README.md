# python-scripts

Репозиторий с учебными Python-скриптами.

## О проекте
Здесь собираются небольшие скрипты и примеры на Python: от базовых задач
до автоматизации повседневных процессов. Проект используется как площадка
для практики и изучения языка.

## Структура проекта
```
python-scripts/
├── README.md          # этот файл
├── scripts/           # готовые скрипты, сгруппированные по темам
├── notebooks/         # Jupyter-ноутбуки (если появятся)
├── tests/             # тесты (pytest)
├── requirements.txt   # зависимости
└── .gitignore         # игнорируемые файлы
```

## Быстрый старт
1. Установите Python 3.10+.
2. Создайте виртуальное окружение и активируйте его:
   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Linux/macOS
   .venv\Scripts\activate           # Windows
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите нужный скрипт:
   ```bash
   python scripts/<имя_скрипта>.py
   ```

## Готовые скрипты
| Скрипт | Описание | Запуск |
|---|---|---|
| `scripts/hello.py` | Пример структуры скрипта | `python scripts/hello.py` |
| `scripts/memory_check.py` | Оценка оперативной памяти (RAM, swap, топ процессов) | `python scripts/memory_check.py --verbose` |

Опции `memory_check.py`: `-v/--verbose` — топ процессов, `-n/--top N` — число процессов,
`-w/--watch SEC` — обновлять отчёт каждые SEC секунд.

## Требования
- Python 3.10 или новее
- Зависимости перечислены в `requirements.txt`

## Как добавить свой скрипт
1. Создайте файл в папке `scripts/` с понятным именем (например, `csv_report.py`).
2. Добавьте в начало файла докстринг с описанием, примерами запуска и параметрами.
3. Разместите код внутри функции `main()` и вызывайте её так:
   ```python
   if __name__ == "__main__":
       main()
   ```
4. При возможности добавьте тесты в `tests/`.
5. Отдельные изменения оформляйте в Git с описательными сообщениями коммитов.

## Стилистика и качество кода
- Соблюдайте PEP 8 (рекомендуется `black` + `isort`).
- Используйте аннотации типов и `mypy` для статической проверки.
- Проверяйте код линтером `ruff` перед коммитом.
